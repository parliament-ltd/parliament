# Research

Read-only audits of the code as it stands on `claude/almanac-docket-inventory`,
commissioned on 11 October 2026 to ground the refactor plan. Each file is one
audit's report: facts with file paths and line numbers first, the auditor's
assessment after, kept separate.

If a file listed here is missing, that audit did not finish before the session
ended. Run it again from the scope below before relying on the matching section
of `../plan-brief.md`.

| File | Scope |
|---|---|
| `editing-code.md` | What can be salvaged for editing in place. Secretarybird in full (`src/components/core/sbrd/*`, `DocumentCanvas`, `DocumentContext`): the paragraph, comment and suggestion shapes; how editing works mechanically (contentEditable, which events, caret handling, composed input, paste); how tracked changes are computed and drawn; the `/` menu; Enter and Backspace; comments and model replies; accept and clear; Submit Edits; Ripple analysis (trigger, prompt, result). How chat messages are rendered today (markdown, citations, charts, per-message actions, hide, ghost text). Highlights: terms or anchored passages. Notes. Every HTML sink in these files. Then, per requirement of the editing spec: reusable as is, reusable with changes, or not a fit |
| `lab-code.md` | What can be salvaged for the Lab. `EditorView` and every file in `src/components/editor/`; every action in `editorReducer.js`; `editorHistory.js`; `layoutMigration.js`; slots and layouts; the catalogue with a table of every entry (tier, surfaces, slot targets, capabilities, config schema); how web search, voice input and file attach reach the input today; mode files and templates; themes and whether a theme is scoped to the room or set globally; the existing Library screens; the wizard's decision logic; every import of `@dnd-kit`; files that appear unused (`RoomDemo.jsx`, `SchemePicker.jsx`, `hooks/useMode.js`, `catalog/dev-modes.js`). Then: reuse, change, or drop, and anything to rebuild |
| `request-path.md` | How a prompt reaches the model: composer to `ChatContext.sendMessage` to the provider; where the key is read and every call site; every place that spends tokens and whether it is user-started or automatic; how the system prompt is assembled; streaming; tools; the network log; `hostAPI.js` and what tiers and capabilities actually gate. Collaboration mode and Parrots (preset text, storage, how they reach the prompt). The Review modal. First run, tours, ignition, `useShimmer`, `PWAContext`. Voice input in detail. Settings keys and what "Automatic" compression does |
| `security-audit.md` | Headers and the content security policy in full, against a hardened baseline; `index.html`, `public/`, the service worker config; every HTML sink, `window.open`, `target="_blank"`, storage and clipboard use; key encryption and what it does and does not protect; what the network log stores; backups (blocklist or allowlist, what a crafted file could write); what "Delete everything" leaves behind; file parsing; markdown rendering of model output; every privacy claim against behaviour, including whether the browser's speech recognition sends audio away (verified against current sources); the licence; user content in URLs or titles; `npm audit` and `npm outdated`; the spreadsheet library's status; which dependencies could go; whether `dist/` is tracked; a prioritised list of findings; what third-party blocks could reach and the sound ways to host them |
| `state-architecture.md` | The provider tree and each context's value, consumers and update triggers; streaming in detail (what state is set per chunk, who re-renders, whether one conversation and one stream are assumed); `RoomShell` and the per-room bus; lazy loading and the current chunk split; every function in `db.js` and which do full scans; how list screens load and search; routing; module-level singletons, custom events and document-level key handlers; how chrome and room styles are separated in `index.css`; tests, lint errors by rule, type checking, continuous integration. Then: the smallest sound change for per-conversation streams, whether contexts are kept or replaced, what breaks in pop-out windows |
| `popout-prototype.md` | Added 19 October 2026, not an audit: the stage 3 prototype of popping the bar into its own window (`src/views/PopoutPrototype.jsx`), how to run it under the real headers, what the in-app browser could and could not show, and what to look for in a real browser |
| `vault-scope-review.md` | Added 22 October 2026, not an audit: the key vault's scope review (S1, stage 7 piece 8): what a key is up against, the options, and which is most secure. Put to Stefan as C170 |
