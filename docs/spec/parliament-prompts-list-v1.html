  • Each answer lands in its own branch. The room stays on the branch it shows; the branch tabs say when another branch's answer has come.
  • A tick on a prompt or an edit is Hold back, the same field the Collection's foot sets (C298): it changes at once, says so under the bar, and undo: takes it back. A branch unticked sends nothing now, and what waits in it keeps waiting.
  • With prompts in one branch only, the list stays folded and the line says it all; "see what goes" opens it. Comments are not in the list: they are never sent.
  • The branches listed are the room's chat and its plan's other branches. Prompts waiting in another room go when that room is addressed, as ruled.
  • Asking several answerers at once stays as it is today, on one branch, each answer a new branch. Across branches, each branch has its one answerer; several to a branch can come later, if wanted.

2 · As a reply

A prompt that asks rather than asks for a change wants a reply, not an edit. On its row, "as a reply". The model is told to answer it in its reply, and nothing lands in the text: once the reply has come, the prompt's brackets go and its passage stays as it was.

3 · What is stored: shown before building

Ticking and unticking use the field an ask has now, held. "As a reply" needs one more, and the answer that comes in the reply needs a state of its own.

As a reply, sent and answered

{
  id: "m-91c2…:q4f1…",
  num: 242,
  conversationId: "c-201a",
  messageId: "m-91c2…",
  question: "is this too strict? say why",
  passage: "a freeze until March",
  reply: true,
  state: "replied",
  held: false,
  sent: { to: "claude-sonnet-5-5", at: "…" },
  answer: { by: "claude-sonnet-5-5", at: "…",
            inReply: "m-a7d0…" }
}
  • reply: optional, true for "as a reply"; a prompt without it is answered in the text, as now.
  • state: "replied": a new value beside open, answered, accepted and taken back, for a prompt whose answer is the reply; answer then names who answered, when, and the reply, with no words of its own.
  • No migration: no record is rewritten, and no store, index or database version changes. Backups carry the field and the state from this version on; one made before reads as now.
  • An older Parliament restoring a newer backup drops reply, and shows a replied prompt as sent, never sending it again.

4 · To rule

  1. Each branch answered by its own answerer, as to: does, the line naming each; rather than one answerer for every branch ticked.
  2. The stored change: reply on a prompt, and the state replied with its answer, as section 3 shows.
  3. A prompt answered as a reply leaves the text, its passage as it was, and its card says "answered in the reply".
  4. The order: the list and the send by branch first, with no stored change; then "as a reply".
