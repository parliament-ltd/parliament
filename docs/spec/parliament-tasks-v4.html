Tasks, v4

v3 with your two notes on it. A task now has a kind, picked from pills as its model is: a prompt to a model, a search of a source, a command, or none, when it is yours. So a command can sit between two prompts: compare the drafts, export them, open a room. A command never runs by itself: a run puts it in the bar, the line under the bar says what it will do, and it waits for your Enter.

Rooms are named by their number, as the strip names them ("Room: 204"), and branches by theirs (207a), never by the name of a room's layout. The rest is v3.

1 · The board

A task's kind shows as a small pill before its model or its command; a task of yours shows none. Where its answer lands is named by number: its branch (207a), or the room it goes into (room 204).

  • A command is checked as it is written, with the line the bar would show under it; one the bar would refuse cannot be kept.

3 · A command between prompts

One by one, a run that reaches a command puts it in the bar, as if you had typed it, and waits there, as it waits at a task of yours. The line under the bar says what Enter will do and what it costs. Enter runs it and the run goes on; Escape leaves it, and the run waits until you run it or tick it.

The barcompare:207a 207b

  • Never on its own: a command can change or delete what you have, or cost money, so each waits for your Enter, as anything typed in the bar does. One that asks for a second Enter asks for it here too.
  • Only you write a task's command. A model's answer or a source's text never becomes one, as text from outside never runs a command now.
  • All at once, the commands wait until the rest have gone, then come to the bar one at a time.

4 · Flow

One by oneEach after the one before, in order, so each model reads what came before it. A task of yours, or a command, holds those after it until you tick it or press Enter.
All at oncePrompts and searches sent together, each in its own chat; commands after, one at a time; yours hold nothing up.
  • With a model, the task's own name and description go with each of its prompts, so each knows what it is part of. A task with a kind and no sub-tasks is sent, searched or run as itself.
  • The flow can change until the task first runs.

5 · What is stored: shown before building

As v3, with a command's line on a step, and rooms held as the chats they show.

A task

{
  id: "d-81…", num: 207,
  title: "Grant application",
  description: "The two-year grant…",
  model: "claude-sonnet-5-5",
  rooms: ["c-204…"],
  flow: "oneByOne",
  doneAt: null,
  branches: [ … ], order: [ … ]
}

A command sub-task

{
  id: "s-5d02…",
  status: "ready",
  title: "Compare the two drafts",
  command: "compare:207a 207b",
  prompt: "",
  model: null,
  condition: null
}
  • The kind is read from what a step holds: command a command, todo yours, a source for its model a search, a model a prompt. Nothing stores the kind twice.
  • command: one line, up to 2,000 characters, kept only as you wrote it; its prompt stays empty, so an older Parliament sees an empty step and runs nothing.
  • rooms are the chats the rooms show (chat ids), so "room 204" is chat 204. A sub-task sent into one goes into that chat, after what is there; the chat stays in its own place in Records.
  • The rest as v3: description, model, flow, doneAt on a task, title on a sub-task. No migration; a restore checks each field.

6 · To rule

  1. v3's six points, as drawn there.
  2. Kinds: none (yours), prompt, search and command, picked as pills before the model; a sub-task starts with its task's.
  3. A command never runs by itself: a run puts it in the bar with its line, and waits for your Enter, or a tick.
  4. Rooms and branches by number: "room 204" sends into chat 204, after what is there; "207a" is a branch of the task; no layout names.
  5. The stored change: v3's fields, with command on a step and rooms as chat ids.
